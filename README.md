# VOYAGER STAGE

5명의 안무·대형·카메라를 편집하고 카메라 번호별 MP4 영상을 출력하는 브라우저 앱입니다.

웹 버전: https://kimdongyoung27.github.io/VOYAGER/

## 실행과 배포

Node.js 24와 pnpm을 설치한 후:

~~~sh
pnpm install
pnpm dev
~~~

Windows의 기존 설치 폴더에서는 실행.cmd를 더블클릭합니다. Chrome 또는 Edge 데스크톱에서 사용합니다.

main에 push하면 GitHub Actions가 테스트와 빌드를 실행하고 GitHub Pages를 갱신합니다. Pages용 빌드는 pnpm build:pages, 일반 호스팅 빌드는 pnpm build입니다. API 키와 별도 서버는 필요하지 않습니다.

## 편집

- 멤버: 은유·지겸·서우·이혁·도경. 멤버마다 몸체 색상과 위치·회전·크기·표시 여부·색상 키를 편집합니다.
- 모션/음악 목록 위 업로드 버튼으로 같은 리그의 Mixamo FBX와 MP3/WAV를 추가합니다. 첫 FBX는 With Skin이 필요하며, 처음 실제 FBX를 추가하면 더미 샘플 에셋과 클립을 제거합니다. 파일은 브라우저에서 처리합니다.
- 목록의 +는 선택 멤버에, 사람 아이콘은 5명에게 모션을 추가합니다. 목록에서 트랙으로 드래그해 배치할 수도 있습니다. 기존 클립을 덮어쓰지 않고 빈 공간에 이어 붙입니다. 공간이 없으면 전체 길이를 늘립니다.
- 클립 가운데를 드래그하면 이동, 양끝 손잡이는 트림입니다. 같은 멤버 트랙의 클립은 서로 겹칠 수 없습니다. 이전에 겹쳐 있던 프로젝트를 열면 소스 순서대로 이어 배치합니다.
- Ctrl/Cmd 클릭은 선택 토글, Shift 클릭은 선택 추가입니다. 빈 트랙을 드래그하면 영역에 걸친 여러 클립을 선택합니다. 선택한 클립들은 함께 이동하고 Del로 한 번에 삭제합니다. 인스펙터의 시작·길이·속도 등도 선택한 클립들에 적용합니다.
- 재생 시간은 위쪽 재생 헤드를 직접 잡아 끌거나 키보드로 탐색합니다. 클립·빈 트랙·선택 상자 드래그는 재생 시간을 바꾸지 않습니다. 시간 눈금과 음악 파형도 재생 헤드를 끌지 않습니다.
- 패널 경계선으로 무대/타임라인 높이와 좌우 너비를 조절합니다. 작은 창에서는 상단 패널 버튼을 사용합니다.
- 숫자는 좌우 드래그 또는 클릭 후 직접 입력합니다. Shift는 미세 조절, Ctrl은 간격 맞춤, Esc는 취소입니다. 한 번의 드래그는 실행 취소 한 번으로 복원합니다.

## 키프레임과 카메라

- ◆ 키프레임 열기로 키 트랙을 펼칩니다. I는 선택 대상의 전체 변환을 저장합니다. 자동 키를 켜면 숫자 편집도 키로 저장됩니다. 끄면 기존 키에서는 그 키를, 키가 없는 시간에서는 움직임의 기준값을 바꿉니다.
- 키 마름모를 드래그하면 시간을 바꿉니다. 선택 후 Del로 삭제하며, 인스펙터에서 시간과 보간을 바꿀 수도 있습니다. 같은 속성의 같은 프레임에서는 도착 키를 대체합니다.
- 기본 작업 화면은 독립된 편집 뷰입니다. 편집 뷰를 회전·이동해도 카메라 구도와 키프레임은 바뀌지 않습니다. 오른쪽 위 작은 화면은 활성 카메라 미리보기입니다.
- 카메라 탭에서 카메라를 여러 개 생성하고 각각 이름·위치·회전·화각·줌·투영·녹화 구간·키프레임을 저장합니다. 새 카메라는 현재 편집 구도에서 생성됩니다. 기존 카메라에 편집 구도를 복사할 때는 편집 뷰 구도 적용을 누릅니다.
- 0 또는 숫자패드 0으로 활성 카메라 뷰와 편집 뷰를 오갑니다. 숫자패드 1/3/7은 정면/우측/상단, Ctrl을 함께 누르면 반대편입니다. 2/4/6/8 회전, Ctrl+2/4/6/8 이동, 9 반대 방향, 5 원근/직교, . 선택 확대, +/- 줌, / 선택 멤버만 보기입니다. 이 조작은 편집 뷰에 적용됩니다.
- 무대·대형 탭은 군무 전체 변환, 무대 위치 프리셋과 군무 대형을 편집합니다. 자동 연결은 이동 거리에 맞는 시간과 부드러운 가감속을 적용합니다.

## 카메라별 MP4 출력

영상 출력에서 출력할 카메라를 체크하고 카메라별 시작/종료 시간을 지정합니다. 비율·해상도·FPS·음악 포함 여부는 출력 설정을 따릅니다.

- 각 카메라를 독립된 MP4 파일로 생성합니다. 파일 이름에는 CAM01, CAM02 등 카메라 번호가 들어갑니다. 여러 카메라를 출력하면 MP4들을 ZIP에 담고, 각 파일도 개별 다운로드할 수 있습니다.
- 장면을 지정한 시간에 프레임 단위로 평가하고 WebCodecs/Mediabunny로 H.264 MP4를 만듭니다. 2초·30FPS 영상 트랙은 60프레임입니다. 실시간 녹화 속도와 관계없이 프레임을 순서대로 인코딩합니다.
- 음악은 각 카메라의 시작 시간에 맞게 잘라 AAC로 인코딩합니다. AAC 프레임 패딩 때문에 파일 전체 길이는 영상 트랙보다 수십 ms 길 수 있습니다.
- MP4 인코딩을 지원하는 브라우저가 필요합니다. 지원하지 않으면 출력 오류를 표시하며 다른 형식을 MP4로 이름만 바꾸지 않습니다. 출력 중 취소할 수 있습니다.

## 저장과 범위

프로젝트 메뉴에서 브라우저 저장, JSON, 에셋을 포함한 프로젝트 ZIP을 지원합니다. 브라우저 저장은 현재 브라우저와 사이트에 종속되므로 다른 컴퓨터로 옮길 때는 ZIP으로 백업합니다. 카메라 목록·독립 키프레임·녹화 구간도 프로젝트에 포함됩니다.

같은 캐릭터/기준 포즈의 FBX가 지원 범위입니다. 서로 다른 체형의 범용 리타게팅, 개별 본 편집, 발 고정 IK, 충돌 회피는 지원하지 않습니다. 수평 Root Motion은 기준 Hips에 고정하며 월드 이동은 위치·대형 트랙으로 관리합니다. 실행 취소는 최근 40개 편집을 보관합니다.

## 검증

~~~sh
pnpm fixtures # 선택: 실제 FBX 통합 검사 파일
pnpm test
pnpm build:pages
~~~

자동 테스트 34개는 시간 평가, 실제 FBX의 독립 스켈레톤, 트림, 다중 선택 이동/삭제, 겹침 방지, 기존 프로젝트 변환, 카메라 독립 키·녹화 구간·저장, 편집/출력 카메라 분리 등을 검사합니다. 실제 FBX 파일이 없으면 해당 검사 하나만 건너뜁니다.

검증용 FBX는 저장소에 포함하지 않습니다. pnpm fixtures는 공식 Three.js r180 예제에서 내려받습니다. 출처: https://github.com/mrdoob/three.js/tree/r180/examples/models/fbx . Metronome-120bpm.wav는 생성한 테스트 신호입니다.
